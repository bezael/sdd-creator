# AGENTS.md — bezael/sdd-creator

This repo is a Claude Code plugin with Dominicode skills. SDD (Spec-Driven Development) is an industry methodology — this repo distributes the **Dominicode adaptation** by Bezael Pérez, not the methodology's invention. Keep that framing in all docs and credits ("SDD adaptation by", never "methodology by").

CBRM (Contract Based Review Method) is Bezael Pérez's own named method, so its credit reads "CBRM by Bezael Pérez · Dominicode". Do not rewrite it as an adaptation, and do not rewrite SDD credits to match it.

## Language conventions

- **English**: all documentation — `SKILL.md`, `AGENTS.md`, templates, references, `CHANGELOG.md`, GitHub release notes, `README.md` (with `README.es.md` as the Spanish mirror).
- **Spanish**: announcement copy (X/LinkedIn posts in `announcements/`, generated by the `release-announcer` skill) and the `plugin.json` description.

## Structure

```
skills/
└── <category>/
    ├── README.md                  ← category index
    └── <skill-name>/
        ├── SKILL.md               ← instructions for Claude Code
        ├── AGENTS.md              ← generated from SKILL.md for other agents (Codex, Cursor, Gemini…)
        ├── templates/             ← templates used by the skill
        └── references/            ← reference material
```

`.claude-plugin/plugin.json` lists the paths of all active skills.

## Adding a new skill

1. Create `skills/<category>/<skill-name>/` with at least `SKILL.md`, then run `node scripts/build-agents.mjs` to generate its `AGENTS.md`.
2. Add `"./skills/<category>/<skill-name>"` to the `skills` array in `.claude-plugin/plugin.json`.
3. If it's a new category, also create `skills/<category>/README.md`.
4. Update the catalog in the root `README.md`.

## Checks

Run `node scripts/check.mjs` before every commit (no dependencies, Node 18+). CI runs the same script on every PR. It fails when:

- a skill in `plugin.json` is missing, its frontmatter `name` doesn't match its folder, or a skill on disk isn't listed
- `plugin.json` `version` differs from the latest released `CHANGELOG.md` entry (bump both together when cutting a release)
- a skill's `AGENTS.md` differs from what `scripts/build-agents.mjs` generates from its `SKILL.md`
- a `references/` or `templates/` path, or a relative Markdown link, points to a file that doesn't exist
- a Markdown table row has more cells than its header (escape `|` inside cells as `\|`)
- a tracked file has CRLF line endings, an SDD credit says "methodology by", or a `dominicode-harness-init` template contains an emoji

`SKILL.md` is the only file to edit. Each skill's `AGENTS.md` is generated from it (same body, no frontmatter): after editing a `SKILL.md`, run `node scripts/build-agents.mjs` and commit both files.

## Evals

`evals/` holds behavior evals for `dominicode-sdd-creator`, run with `claude plugin eval`. They check the hard rules a prompt edit can silently break:

| Case | Asserts |
|------|---------|
| `no-tdd-not-inferred` | "hazlo rápido, es un prototipo" with no runner → proposes a runner, never offers skipping tests, writes no `tasks.md` yet |
| `explicit-no-tests` | "No quiero tests" → asks "not now vs never" and for confirmation before any task list |
| `low-context-intent-first` | "Quiero hacer una app de recetas" → skill fires, interviews the idea, writes no `spec.md` |
| `high-context-triggers` | Detailed feature in a Fastify/SQLite/Vitest repo → skill fires, writes `spec.md` only, no new stack, stops for confirmation |
| `bugfix-no-trigger` | Failing test with a clear repro → skill does not fire, bug fixed directly |

Run them after any change to `SKILL.md`, its templates or its references, and before a release:

```bash
claude plugin eval . --ablation none --scaffold --allow-tools Write Edit --trust-plugin --no-publish -j 5
```

- About $3 and 2 minutes for the full suite (5 cases × 3 runs). Use `--case <name> --runs 1` while iterating.
- `--scaffold` runs each case's `scaffold.sh` to create its fixture repo; only use it on cases from this repo.
- `--ablation none` skips the no-plugin baseline arm, which would double the cost and leave the `Skill` graders unscored.
- Results go to `evals/results/` (gitignored). Add `--keep-temp` to inspect a run's workspace and `trace.jsonl`.
- `Write`/`Edit` graders match the tool's JSON input. Anchor them on `"file_path"`, or a file's content will match too.
- They are not in CI: each run spends real model tokens on your account.
